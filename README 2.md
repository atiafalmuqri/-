# تحليل الحوكمة في القطاع غير الربحي السعودي

مشروع Python لتحليل البيانات القانونية المرتبطة بالجمعيات والمؤسسات الأهلية في المملكة، ومقارنته ببيانات الجهات المفتوحة. يُستخرج النص من اللائحة التنفيذية وقواعد الحوكمة عبر OCR، ثم يُصنَّف حسب موضوعات الحوكمة، ويُرصد فيه المتطلبات الصريحة. ويُحلَّل ملف الجهات إحصائياً مع فحص جودة البيانات.

> **تنبيه:** النتائج مؤشرات للتوعية، ولا تُعد حكماً قانونياً ولا دليلاً على امتثال جهة أو مخالفتها.

## أهم النتائج

- **المواد:** 129 مادة من اللائحة و47 مادة من قواعد الحوكمة، بتسلسل كامل وبلا تكرار.
- **الجهات:** 2,723 سجلاً، بنسبة اكتمال 100% في الأعمدة الأربعة. الرياض 29.3% ومكة المكرمة 16.3% من الجهات.
- **الحوكمة:** لا يحتوي ملف الجهات على درجات حوكمة، ولم يُقدَّم ملف درجات منفصل، لذلك لم يُحلَّل توزيع الدرجات.
- التفاصيل والحدود في [`reports/final_report_ar.md`](reports/final_report_ar.md).

## المتطلبات

- Python 3.12 أو أحدث، ثم `pip install -r requirements.txt`
- **Tesseract OCR** مع حزمة اللغة العربية `ara`:
  - Ubuntu/Debian: `sudo apt install tesseract-ocr tesseract-ocr-ara`
  - macOS: `brew install tesseract tesseract-lang`
  - Windows: ثبّت Tesseract من مشروع UB Mannheim، واختر حزمة Arabic أثناء التثبيت.
  - Google Colab: `!apt-get install -y tesseract-ocr tesseract-ocr-ara`

## إعداد المدخلات

لا تُرفع ملفات PDF ولا ملف CSV إلى هذا المستودع، لأن حقوق إعادة نشرها غير مؤكدة. ضع الملفات في `data/raw/` بالأسماء التالية:

| الملف المطلوب | الوصف |
|---|---|
| `regulation_executive.pdf` | اللائحة التنفيذية لنظام الجمعيات والمؤسسات الأهلية |
| `governance_rules.pdf` | قواعد حوكمة الجمعيات والمؤسسات الأهلية (النسخة الثانية) |
| `Charities_-_Dashboard_2.csv` | بيانات الجهات غير الربحية من بوابة البيانات المفتوحة |
| `governance_scores.csv` | اختياري: ملف درجات حوكمة منفصل إن توفر |

يمكن الحصول على اللائحة وقواعد الحوكمة من الموقع الرسمي للمركز الوطني لتنمية القطاع غير الربحي. أما ملف الجهات فيمكن تنزيله من منصة البيانات المفتوحة المعتمدة في المملكة. تحقق من شروط الترخيص قبل إعادة توزيع أي ملف.

**ملاحظة:** لم يُختبر التشغيل في Google Colab، وإنما على بيئة محلية (Python 3.12 وTesseract).

## الاختبارات

- `python -m unittest discover` لا يجد أي اختبار، لأن الاختبارات مكتوبة بأسلوب pytest.

## التشغيل

```bash
python run_pipeline.py          # ينفّذ المسارين ويكتب المخرجات والرسوم
python -m pytest tests/         # يتحقق من الدوال والمخرجات
```

أو افتح الدفتر `notebooks/nonprofit_governance_analysis.ipynb` وشغّله من البداية. في Colab يلزم رفع المشروع وتثبيت Tesseract، وقد يلزم تعيين `NONPROFIT_PROJECT_ROOT` إن اختلف مسار المجلد.

يُخزَّن نص OCR لكل صفحة في `data/processed/ocr_pages/`، فلا تُعاد عملية التعرف الضوئي إلا عند الحاجة. احذف هذا المجلد لإعادة الاستخراج من الأصل.

## ملفات التدقيق

- `extraction_sequence_summary.csv`: المتوقع والمستخرج والمفقود والمكرر لكل وثيقة.
- `extraction_audit.csv`: تدقيق لكل مادة (صفحات، طول النص، ترويسة تقريبية).
- `human_review_queue.csv`: المواد التي تحتاج مراجعة بشرية، مع السبب.
- `rejected_header_candidates.csv`: الترويسات التي خرجت عن التسلسل.
- `classification_review_sample.csv`: عينة 40 مادة للمراجعة البشرية. أعمدة التسمية البشرية فارغة عمداً.
- `fuzzy_heading_visual_check.csv`: نتيجة التحقق البصري من المواد الـ11 ذات الترويسات التقريبية (قراءة المساعد على صور الصفحات، وليست مراجعة بشرية).
- `official_source_verification.csv`: نتيجة التحقق من مطابقة الملفين لأحدث نسخ منشورة في جريدة أم القرى.

المقتطفات الكاملة من نص المصدر تُحفظ في `data/processed/` ولا تُنشر.

نموذج المراجعة البشرية للتصنيف `data/processed/classification_review_form.xlsx` يحتوي نص المواد، لذلك لا يُنشر. خاناته البشرية فارغة، ولم تُملأ أي تسمية.

## المنهجية باختصار

1. **OCR:** تحويل كل صفحة إلى صورة بدقة 250 نقطة لكل بوصة، ثم التعرف عبر Tesseract بلغة `ara`.
2. **تقطيع المواد:** تُقبل ترويسة المادة إذا كان رقمها هو التالي في التسلسل، وتُسجَّل الترويسات المرفوضة في `rejected_header_candidates.csv`.
3. **التصنيف:** قواعد كلمات مفتاحية شفافة، مع فحص ثانوي بتشابه TF-IDF بالحروف المتتابعة.
4. **المتطلبات:** جمل "يجب" و"لا يجوز/يحظر" و"بشرط/على أن"، مع مقتطفات لا تتجاوز 15 كلمة.
5. **الجهات:** تنظيف بلا حذف، وأعلام تحقق لكل تكرار أو قيمة مقطوعة.

## حدود المشروع

- دقة OCR تقريبية، وتُقاس بالتسلسل ومطابقة الترويسات، لا بالمقارنة الحرفية.
- التصنيف بالكلمات يخطئ أحياناً (مثل "العضو" في سياقات غير العضوية). نحو 44% من مواد "العضوية" تعتمد على كلمات عامة فقط. لا توجد تسميات بشرية مرجعية، لذلك لا تُحسب الدقة أو F1، والنسبة 53.8% هي اتفاق بين طريقتين آليتين فقط.
- لا يحتوي ملف الجهات على مفتاح ربط فريد، ورقم التسجيل مكرر في 516 سجلاً، لذلك لا يُربط بالنصوص القانونية.
- لم يُراجَع نص كل مادة مقابل المصدر حرفاً بحرف.
- لا تتوفر درجات حوكمة للجهات، ولا يُستنتج منها أي امتثال أو ضعف.
